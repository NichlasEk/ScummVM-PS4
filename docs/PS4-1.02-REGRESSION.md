# PS4 1.02 regression investigation — 2026-09-19

The user reports jerky pointer motion and CE-34878-0 when attempting to add
a game with the standalone 1.01 package. The screenshot identifies ScummVM
PS4 but does not establish the exact failing operation or stack trace. An
async question about the precise step is pending. No physical crash log has
been obtained, so do not call the crash fixed until the user retests.

## Confirmed defect

The installed OpenOrbis `bits/alltypes.h` defines mode_t as unsigned int
before its later unsigned-short definition can take effect. This shifts
`struct stat.st_size` to byte 80 rather than the PS4 kernel ABI's byte 72.
The application reads st_blocks in place of st_size. PICE's detector showed:

- KSVGA.KRO: actual 45,874,014 bytes; guest size 89,598 (rounded-up blocks).
- E_KLANG.KRO: actual 32,611,279 bytes; guest size 63,694.
- MD5 prefix hashes were correct, ruling out a wrong data directory.

`compat/ps4/include/ps4-abi.h` predeclares the correct 16-bit mode_t before SDK
headers. Compile-time assertions check mode_t, st_size, st_blocks and the
120-byte stat structure. This applies to every ScummVM application compilation
unit, without modifying the installed SDK or the already-built runtime modules.

## Other changes

- PS4 virtual pointer multiplier reduced from 8 to 2. The speed slider remains.
- Validate getdents record size, name length, terminator and remaining buffer
  before advancing. Invalid records abort the listing instead of being used.
- Reject stale/out-of-range file-browser selection indices.
- Returning up from USB/internal game roots goes directly to the storage list.
- Directory start/failure/completion logs are flushed to the ScummVM log.
- Package version 1.02, title ID SCVM00002, same writable settings/saves.

Synthetic directory-record tests in `tests/ps4/dirent.cpp` pass with address
and undefined-behavior sanitizers. Invalid record lengths, truncated buffers,
unterminated names, embedded separators/NULs and null input are covered.

On console, retest Add Game, enter USB, select a supported game and start it.
If it fails, retrieve `/data/scummvm/scummvm.log` and report the exact last
button/folder used. The added `[ps4-fs]` lines narrow the failing operation.

## Add Game reproduction and 1.02 USB candidate

The emulator reproduced an FSNode::getPath `_realNode` assertion with
`browser_lastpath=/app0/games/dott-missing`. PS4 getcwd can fail, and the
POSIX factory returned a null node for the browser's fallback `.`. The PS4
factory now returns /app0; the browser falls back to the storage root / when
its previous path is unavailable.

The rebuilt package passed PkgTool validation. In the same emulator profile
with the missing path, browsing USB, detecting DOTT and starting its intro
succeeded. Evidence: artifacts/scummvm/regression-1.02-final.log and profile
scummvm.ini with the new tentacle entry. User also reported it appears to work.
Physical-console retest remains necessary.
