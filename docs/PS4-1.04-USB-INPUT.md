# PS4 1.04 candidate — 2026-09-19

Physical-console feedback rejects 1.03: USB 0..7 appeared without usable game
files, and pointer motion was still both coarse and slow. Do not describe
1.03 as hardware validated. Exact input device and console FTP details were
requested and remain pending; older repo history mentions 9.60/GoldHEN 2.4b17.3
but does not establish the user's current environment.

## Corrections

- Opening a mount-point directory is no longer treated as proof of a USB
  device. Validate directory records and require an entry other than dot/dotdot.
  Empty USB volumes are intentionally omitted from this game-data browser.
- Inspect populated USB sources with checked temporary credentials before
  attempting any sandbox mount. Do not create eight mappings speculatively.
- App-local mappings now use /scummvm_usb0..7, avoiding empty /usb0..7 aliases
  from the rejected candidate. Public labels remain USB 0..7.
- The SDK framebuffer waits for VideoOut vsync. Report that actual behavior to
  ScummVM so the GUI does not also sleep its own full frame before presentation.
- Pointer integration uses elapsed milliseconds rather than a fixed movement
  per polling iteration. Retain the quadratic near-center response, subpixel
  remainder, speed slider and neutral-axis delivery. Cap pause catch-up at 32ms.

These fix identified code defects. They do not by themselves prove the console
USB mount path or the user's subjective pointer precision. Do not substitute
emulator results for a physical-console retest.

## Diagnostics

Storage messages are explicitly appended to /data/scummvm/usb-diagnostics.log
as well as TTY stdout. In 1.03 they went only to printf/TTY, so instructions to
find [ps4-usb] in ScummVM's own log were incorrect.
ScummVM's scummvm.log now also records [ps4-pointer] update count, elapsed time,
largest polling gap and raw axes after five seconds of active pointer motion.
Retrieve both via console FTP when available.

## Tests

Address/undefined sanitizer tests in tests/ps4/storage.c now simulate eight
openable but empty mount-point directories, an unavailable kernel service,
one real populated source, rate limiting, credential restoration and cleanup
of only the mount created by this process. All pass.

The emulator fixture .tools/emulator-usb has the same scummvm/games/dott
layout as the physical stick. With only /scummvm_usb0 mounted, Add Game's root
